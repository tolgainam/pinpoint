in use

Click, type, dispatch

Click an element and write what is wrong. Each comment becomes a numbered pin that stays on its element and survives a reload. Dispatch sends the whole batch to the Claude Code session named on the pill.

a demo page, three pins, the toolbar at its foot
the problem

Prose is a lossy channel

You spot something wrong in the browser, switch to the terminal, and type "the spacing under the brand header on the explore page is too tight." Now Claude has to reconstruct which element you meant, on which route, in which state. Everything that was obvious on screen — which node, what it looked like, what was around it — never survives the trip.

Pinpoint moves the comment to where the context already is. You click the element. The context comes along for free.

install

Two pieces, about a minute

Add the marketplace and install the plugin

In any Claude Code session. Dependencies install themselves.

> /plugin marketplace add tolgainam/pinpoint
> /plugin install pinpoint@pinpoint-marketplace

Load the browser extension

This copies the extension to ~/.claude/pinpoint/extension, puts the path on your clipboard and opens chrome://extensions. Turn on Developer mode, click Load unpacked, paste the path, then pin the icon. Chrome runs an unpacked extension straight from that folder, so leave it where it is. Setup ends by checking that everything is connected.

> /pinpoint:setup

Open your app and click the icon

Pinpoint activates on localhost and 127.0.0.1 only. The toolbar starts hidden on every page load. Clicking the icon shows or hides it, and grants screenshot permission for that tab. The pill on the toolbar shows where comments go: your project's name, or Choose when you have several sessions open.

You're done when: the icon is pinned, clicking it on your dev page shows the toolbar, and the pill shows your project name. If not, run /pinpoint:doctor.

the payload

What actually lands in your session

Not a description of the element. The element.

claude code — channel event
<channel source="pinpoint" batch_id="20260822-023835-z0fp" count="1">
**1 comment** on http://localhost:3000/ · viewport: 1772x1054 @1x
  · colour scheme: dark · batch: 20260822-023835-z0fp
whole page: ~/.claude/pinpoint/queue/20260822-023835-z0fp/page.png

### [20260822-023835-z0fp#1] make background red and add 32px padding
  - component: `FeatureCard`
  - selector: `[data-testid="feature-history"]`
  - text: "40 years of history — Backfill and replay any point…"
  - screenshot: ~/.claude/pinpoint/queue/20260822-023835-z0fp/shot-01.png
</channel>
  • Screenshots are real PNG files on disk, referenced by absolute path. Claude opens them with the ordinary Read tool, which renders images — no MCP image plumbing involved.
  • The overlay hides itself before every capture, so pins and the toolbar never end up in the shot.
  • Selectors prefer [data-testid], then #id, then a stable class chain, then an :nth-of-type path. React component names come from a fiber walk where they're available.
  • Resolutions travel back. When Claude calls resolve_comment, the pin turns green with a ✓ and the one-line summary. You never switch to the terminal to check.
architecture

How it works

On demand any session

Works everywhere, no flags. Comments wait in the queue until you ask for them.

/pinpoint:comments

Hands-free research preview

Dispatches wake the session on their own. Custom channels aren't allowlisted yet, hence the flag.

$ claude \
  --dangerously-load-development-channels \
  plugin:pinpoint@pinpoint-marketplace
security

A localhost port is a public surface

Any page you visit can fetch() a port on your machine. Three layers stand in the way:

  • The bridge binds 127.0.0.1 explicitly, never 0.0.0.0.
  • Requests from an unrecognised web Origin are rejected, and application/json is required — which forces a CORS preflight the server refuses for unknown origins. That's the layer that actually stops a drive-by page.
  • Comment text is treated as untrusted input in the channel instructions, since anything reaching the session is model-visible.

Set PINPOINT_TOKEN to additionally require an X-Pinpoint-Token header.

honest limits

What it can't do

  • No file:line. React 19 removed _debugSource from fibers, so mapping a clicked element to Header.tsx:42 isn't reliably possible. Pinpoint captures strong identifiers instead and lets Claude grep for them — which works well and depends on no fragile internals.
  • Chrome only, and localhost / 127.0.0.1 only. By design.
  • Screenshot permission is per-tab and per-navigation. Chrome grants activeTab when you click the icon and revokes it on the next navigation. A failed capture tells you why in a toast rather than going quiet.
